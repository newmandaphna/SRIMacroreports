## Part 2 — Expected schema catalog (verification targets, UNCONFIRMED)

The brief names four report families. For each, below is what we expect to verify.
Column lists are **anticipated**, not authoritative; the profiler detects the real
header. Anything the profiler finds that is not listed here is an exception to
investigate, not something to silently absorb.

### 2.1 `ChargesHistoryDetailProviderPatientCode` — the "NewFeeSchedule" variant
**Role in pipeline:** the *charges side*. Source of CPT codes, provider attribution,
billed charges, and contracted/expected amounts. This is the spine for the session
ledger (Phase B) and the `expected_collection` dollar measure (Phase C).

- **Known quirk (MUST handle):** three preamble lines before the real header — a
  `Textbox` row, a date row, and a blank. The header row must be **detected
  programmatically** (scan for the row containing the expected column tokens), never
  `skiprows=3` hardcoded. After the skip, assert the expected columns are present or
  fail loudly.
- **Expected columns (to verify):** Provider (rendering), Patient identifier *(PHI —
  used only as a join/grain key in memory, never emitted)*, Date of Service, CPT/HCPCS
  Code, Modifier(s), Units, Billed/Charge amount, Fee-schedule / Expected / Contracted
  amount, Charge line status (e.g. voided/reversed indicator), Encounter/Charge ID.
- **Expected grain:** one row per **charge line** (patient × provider × DOS × CPT ×
  modifier). Multiple lines per encounter are normal (E/M + add-on).
- **Money columns:** Billed and Expected/Contracted → **Decimal, never float.**
- **Date basis needed:** Date of Service.

### 2.2 `AppointmentsPatientInfoByProviderThenDayThenFacility` — the appointments side
**Role in pipeline:** the *appointments side*. Source of kept / no-show / cancelled
status (the utilization signal) and the reconciliation gate against charges.

- **Expected columns (to verify):** Provider, Patient identifier *(PHI, key only)*,
  Appointment Date (and possibly time), Facility/Location, Appointment Status
  (kept / arrived / no-show / cancelled / rescheduled), Appointment Type,
  New-vs-established / intake flag.
- **Expected grain:** one row per **scheduled appointment**.
- **Date basis needed:** Appointment date (= date of service for kept appts).
- **Note:** no-shows and cancellations are NOT sessions but ARE kept as their own
  status. Never dropped.

### 2.3 `PatientStatement` (GroupingLevel3) — actual cash collected
**Role in pipeline:** the *collected* dollar measure (Phase C, measure #3). Carries
`InsurancePayments` and `PatientPayments`.

- **Expected columns (to verify):** Patient identifier *(PHI, key only)*, Provider
  (maybe), Date of Service, Posting/Payment date, `InsurancePayments`,
  `PatientPayments`, Adjustments/Write-offs (maybe), Payer, CPT (maybe).
- **Expected grain:** one row per statement grouping line (GroupingLevel3 — likely
  patient × DOS × payer or similar). **To be confirmed by profiler.**
- **Money columns:** `InsurancePayments`, `PatientPayments` → **Decimal.**
- **Date basis needed:** Date of Service for bucketing; Posting/Payment date for the
  claim-lag maturity model. **Both must be present** or the maturity model cannot be
  built — flag loudly if payment/posting date is absent.

### 2.4 `AppointmentDocumentation` — note-signed status
**Role in pipeline:** the LEAKAGE section — "sessions held for unsigned notes."

- **Expected columns (to verify):** Provider, Patient identifier *(PHI, key only)*,
  Date of Service, Note status (signed / unsigned / co-sign pending), Note type,
  Signed date (maybe).
- **Expected grain:** one row per clinical note / encounter.
- **Date basis needed:** Date of Service.

## Cross-cutting requirements the profiler will assert

- **Prior-year coverage:** at least one full year of Date-of-Service history *before*
  the target period, plus payment/posting history extending to the export date, or the
  YoY comparison (Phase D) and the maturity model (Phase C) cannot be computed. If
  absent → treat as "lacks prior-year coverage" → export-request path.
- **Date-of-service column present** in each dollar/session source (everything is
  bucketed by DOS, not posting/payment date).
- **Money columns parse as Decimal** (assert no silent float coercion).
- **No unnamed/duplicate header columns** after preamble detection.
